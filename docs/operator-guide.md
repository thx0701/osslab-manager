# 工單托管：給操作者的一頁說明

> 給要叫 bot「走工單／托管」的人看。模型照 SKILL.md 做事；這頁講你要給什麼、會看到什麼、什麼時候會被問。

## 誰做什麼

| 角色 | 是誰 | 做什麼 | 不做什麼 |
|---|---|---|---|
| 你 | 人 | 給目標與邊界；決定未定的業務規則；同意 merge／部署 | 不用寫工單或驗收命令 |
| 經理 | 你正在對話的 bot | 盤點、拆單、派單、重跑驗收、核實審查意見、逐張本機提交 | 不寫產品碼、不自己發明業務規則 |
| 工人 | pi（DeepSeek，預設）／zcode（GLM，備援）；指定時可改 Claude Haiku 5.5（本機 Pro，僅手動派工） | 照工單改碼、跑驗收、寫回執 | 不 commit、不碰正式站、不挪工單 |
| 審查員 | 依序 Grok 4.7 → Codex GPT-6 Astra → GLM-5.3 max，可指定（唯讀） | 高風險單的外部審查 | 不改檔 |
| Relay | `osrelay`（主機有裝時；Codex／Claude Code 當經理） | 保管派工、等待、交接與驗收證據 | 不做判斷、不自動重派 |

## 開口時給三件事

1. **要做什麼**：一句話的目標。
2. **不做什麼**：邊界。沒說的，經理會當成不在範圍內，要擴範圍會回來問。
3. **怎麼算完成**：你會觀察到什麼（例如「每個品項在賣場都看得到規格」）。驗收命令由經理寫。

有權威文件（spec、issue、PR）就指給它，已定的決策不會再問你。

## 你會看到的東西

- **派單前確認清單**：開派前經理會貼「做什麼／不做什麼／怎麼算完成」三行加拆單清單。拆單清單每一張含鏈名與 git worktree：同一條鏈輪流施工、驗收；彼此不依賴的鏈才會同時跑。邊界不對就當場說；沒意見不用回「好」：在 Paseo 且你下過持續目標（goal、做到完）時它自己開施工段，不能自動接力時就在本 session 續辦。
- **一輪一組的提問**：只有錢、權限、庫存、契約衝突這類沒人定過的規則才會問；前提已定的題目一輪問完，每題附建議與例子，答「好」就是照建議。想一題一題就直接說。沉默不算同意。
- **收尾白話摘要**：什麼能用了、你會注意到什麼變化、還有哪些沒驗；「已 merge」與「已套用到正式環境」分開講。

## 三段職責與自動接力

| 段 | 做什麼 | 交出去的東西 |
|---|---|---|
| 規格段 | 跟你對齊目標與邊界、盤點現況、拆單 | 確認清單＋工單檔 |
| 施工段 | 派工人、等待、收回執 | 回執＋工作樹 diff |
| 驗收段 | 重跑驗收、審查、逐條核實、派修復單、本機提交 | commit＋驗證與審查證據 |

規格、施工、驗收仍分段負責；有自動接力能力與持續授權就換，否則留在本 session 續辦。修復迴圈留在驗收段。

每段結束寫一份約 2KB 的交接檔，下一段的新 session 只讀交接檔就開工，不用背前面的對話。在 Paseo 且你下過持續目標（goal、做到完）時，經理自己開下一段；不能時繼續做；只在 context 接近限制或你要求時才交接。新 session 必須在同一 workspace 正常顯示、可點開，刷新仍存在；只有 id 不算接力成功。

## 什麼時候用 Relay

- 裝了 `osrelay` 的主機，Codex／Claude Code 當經理時：托管一律走 Relay，不和手動 helper 混用。好處是跨段換 session 不掉狀態、工人比經理活得久、accept 由程式核對證據。
- 沒裝 Relay 的主機：經理用 helper 手動派工，流程相同。
- Paseo 另外提供自動接段：有持續目標時經理自己開下一段；沒有 Paseo 時在本 session 繼續。

## 你要做的決定

未定的業務規則、要不要分 PR／分批部署、merge、部署到正式環境。其他都由經理處理並留下證據。
